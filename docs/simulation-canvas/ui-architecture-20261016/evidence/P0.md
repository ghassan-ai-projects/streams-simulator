## 3. Lifecycle corrections (failing first, then green)

The regression tests were written before their guards and run against the pre-change code. Nine of them fail there:
the seven corrections in the table below plus the two further plant/editor cases. Three more are green guards that
protect the new guards themselves rather than reproducing an old failure — the superseded-run callback (the pre-change
`worldId` check already rejected it), the watcher lifetime, and the post-close refresh — and each is labelled as such in
the table. Measured pre-change transcript (the four stores reverted to `HEAD`):

```text
 ❯ src/app/workspaceStore.test.ts (6 tests | 2 failed)
 ❯ src/app/plantStore.test.ts (10 tests | 1 failed)
 ✓ src/app/reviewStore.test.ts (15 tests)
 ❯ src/app/editorStore.test.ts (10 tests | 1 failed)
 ❯ src/app/reviewLifecycle.test.ts (6 tests | 2 failed)
 AssertionError: expected { phase: 'ready', …(14) } to not match object { phase: 'ready', …(1) }
 AssertionError: expected { worldId: 'w-1', …(11) } to match object { worldId: 'w-1', report: { …(2) } }
 AssertionError: expected 1 to be +0 // Object.is equality
 Test Files  4 failed | 1 passed (5)
      Tests  6 failed | 41 passed (47)
```

| Correction | Guard |
| --- | --- |
| a retained callback of a superseded run must not add observations to the current playback index | `ReviewStore.take` checks the session before touching the accumulator |
| a retained callback of an earlier visit to the same run must not either | session counter, not resource equality |
| a late report for a run that was reopened must not publish | `loadReport`/`loadVerify`/`loadRunDomain`/`finish`/`update`/`resumeFinalLoads` all check the session |
| a refresh after the run was closed must not publish | `refreshCompleted` refuses when the stream is closed. Green guard: the pre-change store published here only once the session guard made the case reachable, so this test protects the new guard rather than reproducing an old failure |
| close must invalidate a pending reload and install no watcher | `WorkspaceStore` session and request counters; `close()` invalidates |
| two overlapping reloads publish in request order | request counter |
| opening the workspace twice must keep the watcher alive | the watcher is replaced, not kept with a stale session. Green guard: at `HEAD` the watcher was kept and still live, so this test protects the pairing of the session guard with the watcher lifetime |
| the plant asked for last wins, including an earlier visit to the same path | `PlantStore` request counter replaces path equality |
| the composition asked for last wins, including an earlier visit to the same path | `EditorStore` request counter |

The vacuous stale-callback test in `reviewStore.test.ts` (which could not invoke a stale callback, because the fake
deletes a disposed follower) was deleted; `reviewLifecycle.test.ts` holds the real cases and drives a retained callback
through `streamFollow(0, …)`. The suite grew from 445 to 466 tests across 100 files.

## 7. Recorded deviation: launch test timers

PLAN P0.8 asks for the launch tests' real-time polling of the panel's 2 000 ms hold to be replaced with fake timers. That
migration was attempted and reverted: with global fake timers in those two files, `@testing-library`'s async queries no
longer resolve (they wait on real timers), and six tests fail or time out. Doing it properly means giving `LaunchStore`
the injected `Clock`/`Scheduler` ports and advancing them explicitly, which is Phase 2's deliverable ("Introduce the
Clock and Scheduler ports and migrate launch/review application timers"). The real-time cost is bounded by a 3 s
`vi.waitFor`, not a fixed sleep, and no production timer changed. The work is carried into Phase 2 by name.

## 8. Notes

- The checkers are TypeScript run by Node's native type stripping, so they are typechecked by `tsc --build` and linted by
  the strict ESLint configuration. `isTypeOnly` on an import clause and an export declaration is deprecated in this
  TypeScript with no replacement; both call sites carry a named disable with its reason.
- Phase 0 records the *current* emitted-stylesheet order (theme tokens after the graph sheets) as the baseline. Phase 1
  must either preserve it or name the change in the register's `emittedCss.note`.
- `boolean-flag-param` fires on any boolean parameter that is not a registered single local fact; the escape is a
  signature that names the choice, which is the doc's intent. The policy is stated in the register.
- The screenshot capture helper (`canvas/scripts/capture-screens.ts`) is developer evidence, not a gate; it was built at
  the end of Phase 0 and is used from Phase 1, where CSS first moves.
- The checker implements 28 rule ids; 27 of them can fire on the current tree, and `emitted-css` is the no-build guard
  in the emitted-stylesheet check.
- No Go file, `test/architecture` file or root `scripts/` file was touched. `make gate-ratchet` is unaffected.
