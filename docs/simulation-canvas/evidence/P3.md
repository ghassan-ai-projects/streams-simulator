# P3 evidence — run journal

- **Date**: 2026-10-12
- **Change**: a run writes two append-only JSON Lines streams while it happens (observer
  `journal.jsonl`, director `sealed/journal.jsonl`), replay rebuilds both and `verify` checks them;
  Explore mode stamps a run unblinded from creation and `score` refuses it. Design:
  [`docs/design/RUN_JOURNAL.md`](../../design/RUN_JOURNAL.md); contract `run-journal-v0.1`.
- **Behaviour**: additive. The trace, ledger, state history, world digest and determinism tuple
  are unchanged (every `verify` and `replay` line of the behaviour pin is identical); `sim_version`
  is not bumped. Two deliberate behaviour changes are listed below.

## Decisions the design left open

| Question | Decision | Why |
|---|---|---|
| A consumer report is not in the command log, so replay cannot write it. How can both streams be replay-identical? | Records are replayable or **session** (`consumer.reported`, reserved `pacing`). A session record is in the file, takes the `seq` of the replayable record that follows it and the `at_ns` of the one before, and is outside the stream digest. | Without it, `verify` would fail for every closed-loop run. The closed-loop acceptance test proves a run with a consumer, an acknowledgement and reports verifies. |
| `clock.advance` carries `await_consumer` in the command log; replay always records it as false (pacing). | The journal's `command` record for an advance carries only `to_ns` (`rules.JournalCommand`, the same rule as a scenario). | Found by the closed-loop test: the director stream differed from its replay at the first awaited advance. |
| When is `run.unblinded` written for a reveal on an open run? | Explore: first director record, at creation. Reveal: at the close, before `run.closed`, `reason: revealed`; replay marks an unblinded artifact unblinded before it ends. | A live record at the moment of the reveal cannot be rebuilt by replay (the reveal is not in the command log). The wall-clock moment stays in the artifact. |
| What does an observation hold? | The adapter's rendered line exactly as the sink received it (a broken line kept as received, flagged `malformed`), not the native event. | The native event carries its pre-perturbation emission `seq`, so a `drop` perturbation would show as gaps, and fields an adapter hides (review finding 2). The observations are now the trace's lines, in order. |
| Where is the seed? | Not in the observer stream: the observer `run.opened` has no seed (the schema forbids it). The director stream starts with its own `run.opened` (`run_id`, `seed`); the artifact keeps the seed. | MCP_SURFACE §4.5: with the seed and the domain a consumer could regenerate the fault-free world (review finding 1). |
| How does an explore run stay unscorable if its flag is cleared? | `RequireBlind` also refuses `mode: explore`; replay fails when the artifact's `unblinded` differs from the stamp it derives. | Review finding 3. |
| Which effector calls are in the observer stream? | Only acknowledged ones, with `model.EffectorAcknowledgement` (the value `OperatorView.Invoke` returns). A declined call is in the director stream (`refused`). | The operator received a refusal, not an acknowledgement. |
| `run.closed` fields | Observer: `incomplete`. Director: `incomplete`, `error`. | `complete` is the negation of `incomplete`. |
| Record shapes for the model records | `command`, `delivery`, `state` nest the model record under the type's name. | The model records have their own `seq` and `at_ns`, which collide with the envelope. |
| Incomplete runs and verify | Journals of a run that ended incomplete are not compared. | Its close (a consumer that never quiesced, a sink error) cannot be reproduced by replay; its trace digest is still verified. |
| Facade constructor name | `journal.NewInDir`, not `Open`. | The facade gate accepts a constructor with an error return only under a `New…` name. |

## Deliberate behaviour changes

1. **`streamsim score` refuses every run stamped unblinded** (`score_failed`: "the run is stamped
   unblinded and is never scored"), explore runs and runs whose truth was revealed on an open run.
   It used to print a scorecard carrying `unblinded: true`; the director's `sim.score` already
   refused (`run_unblinded`). Proof: `TestGradeRefusesARunStampedUnblinded`,
   `TestRequireBlindRefusesOnlyAnUnblindedRun`, `TestExploreRunIsStampedUnblindedAndScoreRefusesIt`,
   `TestExploreRunIsRefusedByScore`.
2. **`verify` and `replay` fail with `replay_mismatch` when a journal stream differs** from
   `journal_digest` / `sealed_journal_digest` in `run.json`, or when a journal file beside the artifact
   differs from the replay. Artifacts without the digests (written before this phase) are not
   compared.

Also found and fixed (deadcode gate failed on `main` already): the facade wrappers
`run.PruneRefusedCalls` and `run.CheckArtifactInputs` had no caller outside the module and were
removed (`make deadcode`); the app layer keeps the functions its own export code uses.
Test-infrastructure: the architecture gates skip `.claude/worktrees` like `.git` (an agent's git
worktree there holds a second copy of the source tree), and so does the function-length tool;
`.claude/` is in `.gitignore`.

## Findings closed

- **R2d-01** (done): `closed_loop_test.go` and `operator_surface_test.go` moved from `internal/director`
