# P5a2 evidence — multi-kind world

- **Date**: 2026-10-12
- **Change**: a domain may declare several kinds and several instance sets. The validated v0.2 document is the
  runtime form (`model.DomainSpec` holds `Kinds` and `Instances`), each world entity carries its kind, and the
  truth solver, suite, audit, score, director and CLI read per kind. Spec:
  [`docs/design/DOMAIN_SPEC_V0_2.md`](../../design/DOMAIN_SPEC_V0_2.md) §2.3 and §3. Closes finding R5a-01 from
  [reviews/P5a.md](../reviews/P5a.md) (M1).
- **Not in this phase**: add-or-narrow overrides, typed links, system entities, the board and named instances
  (P5b). R5a-02 (the id check must admit named instances) stays open for P5b.

## Decisions

| Question | Decision | Why |
|---|---|---|
| Namespacing of channel, fault and effector names | Unique across the whole domain, not qualified by kind; state names are unique within their kind | An event's `channel`, a fault id in a label, an effector in a command, the keys of a profile's `fault_weights` and the adapter mappings stay plain strings that resolve to one declaration, so adapter, perturbation, scoring and MCP are unchanged |
| Profile fault weights | Keys are domain-wide fault ids | Follows from unique fault ids |
| References between sections | Resolve inside the kind (observes, bias, trigger state, dynamics target and inputs, fault `affects`, effector deltas and interlock, detector channels, `expected_effector`, `confirmation_channels`) | A reading, a deviation and a confirmation are entity-scoped; a cross-kind reference would read zero |
| Fault or effector on another kind's entity | Refused by the world | The kind selects the entity's faults and effectors |
| Peer residual | Pools the live entities of the same kind | Peers are like-for-like |
| Instance sets | Several, each with its own template, count and churn, each naming a kind; every kind needs at least one | One id template, count and churn per set |
| Explicit entity ids | Matched to the first set whose template fits; counts checked per set that has ids; an id that fits no set is refused | Keeps R2-02 and extends it |
| Profile `entity_count` | Replaces the default count of the first instance set | Simplest rule that leaves single-set domains unchanged |
| Runtime form | The validated document itself; the P5a lowering and `model.DomainDocument` are removed | Nothing left to lower; pointers need no mapping |
| RNG draw order | Substreams carry entity, channel, fault and effector names (domain-unique); initial entities are created in set order then index order; churn births of set 0 keep `churn/births`, set `i > 0` uses `churn/births/i` | Single-kind worlds draw exactly as before; adding a kind never changes another kind's draws |

## What was built

| Area | Change |
|---|---|
| Contract | `maxItems: 1` lifted on `kinds` and `instances` in both copies of `domain-spec-v0.2.schema.json`; descriptions state the several-kind rules |
| `internal/model` | `DomainSpec` is `{Kinds, Instances, ...}`; `Entities` and `DomainDocument` removed; `Kind` lookups (`StateDecl`, `DynamicsOf`, `ChannelDecl`, `FaultDecl`, `EffectorDecl`) in `kind.go` |
| `internal/domain` | Checks run per kind with document pointers (`lowering.go` and `documentPointer` removed); domain-wide uniqueness of channel, fault and effector names; kind and instance-set cross-checks; `Kind`, `FaultKind`, `StateNames(kind)`, `KindChannelNames`, `FaultCount`, `EffectorCount`, `InstanceSetFor`; `CheckEntityIDs` per set |
| `internal/world` | `Entity` carries its kind and instance set; state, dynamics, channels, clamp and initial value come from the entity's kind; faults and effectors are kind-checked; churn and next index per instance set; `PeerIDs`; `PopulationIDs` replaces `RenderID` |
| `internal/truth` | Peer residual and its noise floor use `PeerIDs` |
| `internal/suite` | Entity drawn from the fault's kind (same RNG draws for one kind); setup calls only for effectors of the entity's kind; population from `PopulationIDs` |
| `internal/audit` | Control fault and channels belong to the injected fault's kind; fits iterate the evidence channels in sorted order |
| `internal/score`, `internal/run`, `internal/deviceworld`, `internal/director`, `internal/cli` | Fault lookup through `Compiled.Fault`; state history of an event covers its entity's kind; binding validation reads the entity's kind; nameplate and `domain validate` totals span all kinds |
| Fixture | `internal/testsupport/testdata/two-kind-plant.domain.json`: tanks (3) and pumps (4), each with state, dynamics, a channel, a positive and a negative-class fault and an effector |

## Behaviour pin changes

v0.2 document (`kinds`, `instances`) instead of the flat runtime shape. No trace, ledger, history, verify, replay,
suite, run or adapter line changed.

## Incidental

- `TestCheckEffectorArgsJudgesWithoutInvoking` shared one world between parallel subtests, which race on the lazily
  built argument-schema cache (reproducible at `-race -count=30` on `HEAD` before this change). Each subtest now
  builds its own world.
- `CheckEntityIDs` reports a template mismatch before a count violation (it needs the set before it can count).

## Known limits

- A profile's `entity_count` applies to the first instance set only; per-set counts in a profile arrive with named
  instances in P5b.
- A fault, effector and detector must live in the same kind as the channels and effectors they name; a plant-wide
  detector across kinds (for example a conservation balance over several kinds) needs the system entities of P5b.
- Run artifacts recorded under P5a embed the same v0.2 `domain_spec` and still replay; artifacts recorded before P5a
  do not, and there is no compatibility with them, by the owner's decision.
