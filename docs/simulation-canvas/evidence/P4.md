# P4 evidence — run report

- **Date**: 2026-10-12
- **Change**: `streamsim report <run-dir> [--format json|markdown] [--out <file>]` summarises a run
  folder as one deterministic document. Design: [`docs/design/RUN_REPORT.md`](../../design/RUN_REPORT.md);
  contract `run-report-v0.1`.
- **Behaviour**: additive. No trace, ledger, state history, artifact, digest or determinism tuple
  changes; `sim_version` is not bumped. One deliberate pin change: the usage text printed by an
  unknown command lists the new command (`failure/unknown-command/stderr` in the behaviour pin).

## Report contents

Run identity and inputs (id, mode, complete and why not, ended, unblinded, sim version, domain and
adapter with digests, seed, sink, time mode, start and end, entity count); the digests the run
recorded; `verification` (trace, observer journal and director journal digests recomputed from the
files and compared with `run.json`: `files_match`, `files_differ`, `not_checked`; not a replay);
counts (emitted, observed, ledger rows, delivered and dropped, each by ledger reason); `truth`
(faults, perturbations, environment faults and effector calls with the world's real outcome, from the
command log and the director stream); `consumer` (name, version, arm, `config_digest` only when the
verdict recorded one); `scoring` (`scored` with the scorecard, `not_scored` for an unblinded run,
`failed` with the reason).

## Decisions the design left open

| Question | Decision | Why |
|---|---|---|
| Markdown and the one-JSON-document rule | Markdown requires `--out`; stdout then names the file. JSON without `--out` is the stdout document; with `--out` the file holds the chosen format | Printing Markdown beside or instead of the document would break CLI_SURFACE §1 for tools; a file keeps both honest |
| What does "verification status" mean without a replay? | Files versus the digests `run.json` recorded (`files_match`, `files_differ`, `not_checked`); replay stays `streamsim verify` | The report must be a pure function of the folder and need no catalog; the name does not claim more than it proves |
| Who may read a report? | Truth sections only when `run.json` exists (`run.ended`) or the run is Explore. A folder cut before `run.json` is reported from the observer journal alone, without reading the ledger or `sealed/` | The report carries the seed, faults and drop reasons; it must not become a way to read ahead on an open Evaluate run |
| Scoring without `--domains-dir` | Grade from the specs the artifact embeds | Keeps the report a function of the folder |
| Effector outcome | The director stream's record, paired to the call by `command_id`, shown verbatim | `silent_no_effect` reads `effect_applied: true` (shadow state only) in the world's own record; the report does not reinterpret it |
