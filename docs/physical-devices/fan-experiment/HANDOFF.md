## 5. Rules and pitfalls

- Binding: each repo's AGENTS.md. In streamsim: files ≤ 300 lines, functions ≤ 15 lines, minimal comments, no consumer knowledge in the binary, domains/devices are data, **never loosen a gate** (caps, allow-lists, coverage floors, test hooks, anything under `test/architecture` or `scripts/`): floors may only rise; a gate change needs the owner's approval line `Owner-approved-gate-change: <reason>`. New-module registrations are not loosening. No `//nolint`. US spelling in strings (`misspell` runs in lint).
- Owner rules (memory): commit each improvement, review before commit; Opus writes code and its tests, Sonnet investigates/reviews, Haiku runs commands/lint/gates (use `model` on the Agent tool); never block on long scripts (run in background); branch per milestone, merge to main only at the end; customer data never in GitHub; browser reviews in the owner's real Chrome (canvas UI rounds).
- Never print or copy secrets (`~/.tamoz/service.env` values, keys). The permission classifier blocks reading that file; source it only inside the worker's shell as the runbooks say.
- zsh has no `PIPESTATUS`: when a gate agent pipes to `tail`, the exit code is lost; write output to a log file and check `$?` separately.
- Gate timing is noisy when several things run at once (Agentic Stream's T7 suite-time budget, streamsim canvas e2e). Rerun alone before declaring a failure real.
- The streamsim binary is `bin/streams-simulator` (the old `bin/streamsim` is stale). `make build` refreshes it; tests that use it skip when it is older than HEAD.
- Writers drift in size: a writer whose context is huge should be replaced by a fresh one briefed from the findings files.
