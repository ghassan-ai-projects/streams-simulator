# plantwire — ubiquitous language

| Term | Meaning |
|---|---|
| Node | The simulated world speaking the plant wire to a host |
| Host | The plant supervisor the node dials |
| Session | One connection: its own `session_id`, both sequences from 0 |
| Birth | `NBIRTH` (kinds once) and `DBIRTH` (one device, its board, boot and current values) |
| Slice | One step of world time; the node sends its data, then `NSYNC`, and waits for `HSYNC` |
| Barrier | The wait for `HSYNC`, capped in wall time; three missed barriers are host loss |
| Lane | Transmit priority (`control` before `data`); `seq` is assigned at transmission |
| Rebirth | `NBIRTH` with the next `bd_seq` and every `DBIRTH`, in the same session |
| Epoch floor | The highest `authority_epoch` the host announced |
| Kind file | One `NBIRTH.kinds` entry without its `kind_digest`, in `*.kind.json`; the interface a device implements (`KindFiles`, `KindSource`) |
| Regular kind file | A kind file is read only as a regular file of at most 1 MiB (`MaxKindFileBytes`), one JSON document, with no member named twice (`ErrDuplicateMember`) and a canonical form (`ErrNotCanonical`: no number beyond the range of a double) |
| Implements | A domain kind names the kind file it implements; `CheckImplements` requires the kind's metrics and commands, safe-stop flags included, as `KindTemplates` gives them, to equal the kind file after canonicalisation, and names the first differing member. It reads kind files only for a domain that implements one, and then only the files of the kinds it implements (`ImplementedKinds`, `SelectKindSources`): a file is known by the kind it declares, or by its file name when it cannot be read or parsed, so a malformed file of another kind is never read |
| Implements checked | What `CheckImplements` returns for a domain that passed: one `{kind, kind_digest}` per implementing kind, an empty list when no kind implements (`model.ImplementsChecked`) |
| Scaffold | `Scaffold` reads kind files, hands them to a scaffold function the caller injects (the plant wire module may not import the component module), and checks that the domain it built implements them: the one entry for a twin |
| Twin rules | A function the caller injects (the plant wire module may not import the component module) that lists everything a twin needs a kind file to state; `kind validate --twin` applies it to a file or to one document on standard input and reports every issue at once (`TwinRules`, `ErrTwinRequirements`) |
| Kind stream | One kind document read from standard input under the limit and strictness of a kind file, named `<stdin>` (`ValidateKindStream`) |
| Capture | The draft kind files of one `NBIRTH` for a person to review: per announced kind the entry without `kind_digest`, the digest announced, the claims, the issues the draft still has and, against kind directories, a comparison with the file of the same name; `{environment, boards, bd_seq, births_seen, taken, later_births?, issues?, kinds}` (`boards` is `[{board, environment}]`, each board's claim) (`CaptureFile`, `CaptureStream`, `ParseCapture`). It writes nothing |
| Birth is a claim | A birth is captured only when it validates against the `NBIRTH` schema, speaks this contract (`ProtocolInvalid`, `ContractUnsupported`), every announced `kind_digest` is recomputed and holds (`KindMisdigested`) and no kind is announced twice, not even under another case (`KindsDuplicated`, also an `inventory_mismatch` of the reference host); `environment` and each board's `environment` are the node's claims too, never verified, but they must not contradict each other (`EnvironmentClaimFault`, an `environment_mismatch` issue; `ErrBirthRefused`) |
| Capture source | A stream of lines read once (`ScanBirths`): a bare `NBIRTH`, or the `record` of a journal `wire` record with `direction` `node`; a line at most 1 MiB (`MaxLineBytes`), a scan at most 32 MiB (`MaxScanBytes`), standard input at most 1 MiB. Members are matched exactly and none may be named twice (`ErrNoBirth`) |
| Observer stream | The only stream a birth is taken from: a record of the director stream is `ErrSealedStream`, any other or missing stream on a wrapped record `ErrNotObserver`; the stream is checked before the record is accepted |
| Provenance | Which birth was captured and what else the source held: `births_seen`, `taken {line, bd_seq}`, `later_births` (with `same_content`), and the issues `rebirth_differs`, `birth_line_unreadable`, `scan_truncated`; the first birth is taken, never the last |
| Claims | The members of a draft that came from the board and that nothing verified: `risk_class`, `safe_stop` and the bounds of an `args_schema`, as pointers (`claimsOf`) |
| Target | The path a draft would be saved to, one rule (`KindFileStem`, `CompareWithFiles`): an existing file's path for `same`, `differs` and `unreadable`, the colliding file's on a name that differs only in case (`kind_name_collision`), else `<kinds dir>/<kind name with : as _>.kind.json` |
| Stand-in | A scripted plant wire node for tests (`internal/plantwire/internal/standin`): a hardware board behind a gateway that births kind files, plays readings, link loss and rebirth in script time and answers commands from a script. Test support: imported by tests only, no I/O, no clock, never part of the binary |
| Environment | `simulated`, `hardware` or `mixed`. A board is `simulated` or `hardware` (`NBIRTH.boards[].environment`, required); a node is one of the three and must agree with its boards (`simulated`: every board simulated; `hardware`: every board hardware; `mixed`: at least one of each). A simulated world's boards are all `simulated` and its node can announce only `simulated` (`ErrBadOptions` otherwise, `model.Board.Environment` is run data, never a domain-spec member) |
| Origin | The environment of the board a device is born on (`DBIRTH.board`); nothing else (a name, a kind, a metric) may infer it |
| Host environment | What a host is set to (`host.Options.Environment`, `plantwire host --environment`, checked by `CheckEnvironment`): `simulated` or `hardware` accepts only a node of exactly that environment, `mixed` accepts all three; a node that contradicts its boards is refused by every host (`EnvironmentFaultFor`, the one predicate the host and capture share) with `environment_mismatch`, and `host.Report.Reason` says which rule |
| Kind files for | `WithKindFiles` reads kind files and hands them to a caller-injected function, so a surface can use them without the plant wire module knowing the use (`Scaffold` is built on it) |
| Safe stop | A command the domain flags `safe_stop: true` on its effector; the node announces it as `safe_stop` in `NBIRTH.kinds` and runs it without freshness, epoch or policy checks. There is no node option that names safe stops: the announced flag and the executed behaviour are the domain's, and `implements` holds them equal to the kind file |
| Relay | The simulator between an edge gateway and the real host, alone for hardware or with a simulated world beside it (Mixed node): the host of one gateway link and the one node of one host link (`plantwire relay`, `domain.Relay`, `app.Relay`). It carries records, owns only the envelope and originates nothing a host or a gateway did not say, except the rebirth requests, offline states and deaths a lost link needs |
| Pass-through | What the relay does to a hardware record and to a host command: the content is exactly as received (values, qualities, times, boot ids, command ids, every safety member), only `session_id`, `seq`, and the `NBIRTH`'s `bd_seq` and `prior_last_seq` are the relay's own. It is structural: `RelayOptions` has no fault, perturbation or script member and no relay file may name that code |
| Admission | The handshake checks a host makes of a node's birth, one predicate for the reference host and the relay (`Admission.Refusal`, `Admission.Reason`): protocol range, environment, contract, version, inventory (digests and duplicates) |
| Moves | What the relay's state machine returns for one event: the records to send up and down, the lines to journal, the links to close and an error that ends the relay (`Moves`) |
| Sequence table | The pairs (gateway `seq`, relay `seq`) of the last 4096 records carried in a host session, with which `NSYNC.through_seq` is mapped up and `HSYNC.through_seq` down to the last carried record at or below it (`seqTable`); an unmapped barrier is dropped |
| Relay journal | The relay's observer `wire` session records, directions `gateway` (received), `node` (sent to the host), `host` (received) and `relay` (sent to the gateway); a carried record is two consecutive lines, a dropped one only the first (`run.WireTrace`; in a mixed session the run's own journal) |
| Mixed node | A relay that also runs a simulated world (`plantwire relay --domain`, `domain.NewMixedRelay`): one node toward the host, `environment: mixed`, one `NBIRTH` merged from the gateway's (hardware boards) and the world's (simulated boards), kinds shared by name only when their `kind_digest` is equal. The world is an ordinary node `Session` whose link is a pair of in-process mailboxes (`uds.SimLink`), advanced slice by slice by the host's `HSYNC` and not paced to the wall clock (D-71) |
| Router | How the mixed relay sends a host record down: a `DCMD` or `DQUERY` by the origin of its device (`Relay.OriginOf`: the board that announced it), an `HSYNC` to the side whose `NSYNC` it answers; a device on no board is refused `unknown_device`. There is no path from a simulated record to the gateway: `SimMoves` has no member for it |
| Collision | A gateway that announces a board or a device the world also has, or a kind of the same name with another `kind_digest`, is refused `inventory_mismatch` with the rule in `reason` (`Collision`) |
| Stray device | A record that names a device its side did not announce; dropped and counted, so one origin can never speak for the other |
| Field trace | The records a gateway sent, in the order the relay received them, one `{ordinal, record}` canonical line each, in `field-trace.jsonl` of the run folder; an input of the run, its digest in `run.json` (`run.FieldTrace`, `run.ReadFieldTrace`) |
| Interrupt | A local control at the node: hold (every `DCMD` in scope refused `local_control`), approve each command (a `DCMD` waits, answered `queued`, until approved, denied or past its deadline) or emergency stop (the safe stop of each device in scope, then a hold latched until released); scoped to all, a board or a device; hold outranks approval outranks nothing. The node may only refuse or stop (`domain.Interrupts`, `domain.InterruptGate`) |
| Control socket | The owner-only unix socket of a running `plantwire connect` that carries one `node-control-v0.1` request per line and answers each with one line (`--control-socket`; `app.ControlPort`, `uds.ControlServer`) |
| Interrupt log | The node's controls and decisions as records of `interrupts.jsonl` (`interrupt-log-v0.1`): inputs (inventory, control, command, clock, flush), decisions (reply, verdict, resolve, stop) and effects; replaying the inputs through the rules reproduces the decisions (`domain.ReplayInterrupts`, `app.VerifyInterruptLog`) |
| Replay plan | The pure plan of a replay (`PlanReplay`): the recorded node records in order, split at the recorded `NSYNC`s, with every board and the node rewritten `simulated`; what cannot be played is skipped and counted |
| Connected session | `plantwire connect`: a session plan run until it is interrupted, a node to the host with no gateway, the mixed relay with one; an interrupt ends it into an ordinary run folder (`app.Connect`, `app.CheckConnect`) |
| Session plan | `session-plan-v0.1`: the plant, the host socket, an optional gateway socket and the bindings; checked against the domain and its kind files (`domain.CheckPlan`) |
| Binding | A plant instance that is a real board: the board and device a gateway must announce, with the instance's kind file (`domain.Bound`); checked at each gateway handshake (`BindingIssues`) and the instance withheld from the world's births (`Options.Bound`, the world's node options: a binding never touches a record the gateway sends after admission) |
| Note | What the relay asks the journal to record beside the wire: an `origin` per device born to the host and a `binding` outcome per handshake of a plan that binds an instance (`domain.Note`, `Moves.Notes`) |
| Replay | `plantwire replay-trace`: a node that plays a field trace to a host. It announces itself and all its boards `simulated`, has no gateway option, refuses every command (`not_ready`, or `unknown_device`) and is barrier-paced by its own `NSYNC` (`app.ReplayTrace`) |
| Twin report | `plantwire twin-report`: the domain that implements the board's kinds replayed in a fresh noise-free world with the commands the board accepted, compared per device and metric with the recorded readings (`twin-report-v0.1`; `domain.EvaluateTwin`). It measures the twin, not a consumer |
| Applied command | A host `DCMD` to a device of the board that the gateway's `DRECEIPT` accepted, that its `DRESULT` did not report failed and that no interrupt refused or left waiting; only these drive the twin. Every other command is listed with its `not_applied` reason |
| Tolerance | The absolute distance within which a board reading agrees with the twin: declared per device or kind metric, else `span_fraction` of the metric's `eu_range` span, else none (`cannot_judge`); never invented |
| Divergence | A named stretch of consecutive compared readings of one metric beyond its tolerance, with its interval, its worst point and the commands in force there |
